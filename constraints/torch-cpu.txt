# TIER 2 -- installed explicitly, NEVER resolved by requirements/lock/*.txt.
#
# Why this file exists at all:
#
#   1. On PyPI's manylinux wheels, `torch` IS the CUDA build. If torch appeared
#      in a .in file, `uv pip compile --python-platform x86_64-unknown-linux-gnu`
#      would pull ~2.5 GB of nvidia-* wheels into the CI lock. CI never needs
#      torch (it runs the tfidf_svd embedding backend), so it must not be there.
#
#   2. `torch==2.9.1` and `torch==2.9.1+cpu` are DIFFERENT versions to pip. The
#      local version tag `+cpu` cannot survive a normal resolution, so pinning
#      it inside the lock would trigger a full re-download of a torch that is
#      already installed.
#
# Nothing in the published setup installs these. `python -m venv .venv` plus a
# lock file gives an environment that runs the whole offline test suite and
# re-scores the experiment from stored traces. This file exists for the one
# thing that needs more: reproducing the MiniLM embedding backend that both
# frozen arms used.
#
# Install:
#   pip install -r constraints/torch-cpu.txt --extra-index-url https://download.pytorch.org/whl/cpu
#
# Verify what you actually got:
#   python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
#   -> 2.9.1+cpu False

torch==2.9.1+cpu
